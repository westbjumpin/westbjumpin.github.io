Weapon Animation — Troubleshooting

Symptom → cause → fix, for the failure modes this system is built around.

Nothing animates at all

The template hasn't been generated. Run Tools ▸ AFPS ▸ Generate Weapon Animator Template once per project, then press Set Up Animations on the weapon.

No override controller. The Animator is running the template directly, which has only placeholder clips. Press Set Up Animations — the validation box reports this as an error.

Every slot is empty. The inspector lists empty slots as (procedural fallback). A clip dragged into a slot only counts if it is not one of the shipped placeholders; a clip you happen to have named AFPS_Fire is treated as empty by design.

The weapon jitters, drifts, or fights itself

The Animator is on the weapon root. AFPS_WeaponSystem writes the root's local position and rotation every frame from the procedural channels, so an Animator there is in a tug of war with it. Move the Animator onto the weapon model child. The validation box reports this as an error.

Apply Root Motion is on. It drives the model's own transform out from under the root. Turn it off on the Animator (it is forced off at runtime, but fix the asset).

The clip translates the whole rig. Set Root Transform Position (Y and XZ) to Bake Into Pose on the FBX's Animation tab.

The draw shows one frame of T-pose / bind pose

That frame is the Animator rebinding as the model is re-activated. The shipped runtime already handles it (Play followed by Animator.Update(0f)), so if you still see it you are most likely entering the Equip state from your own code or from a trigger. Use Play/CrossFade and call animator.Update(0f) on the same frame.

The equip animation sometimes doesn't play

A trigger was used somewhere. Weapon switching re-activates the model, which rebinds the Animator and clears its parameters — triggers set on that frame are dropped. Never use triggers in a weapon graph; see Extending the system.

Four arms during climbing, mantling or ledge hanging

Use Arms is on. A full rig carries its own arms, so the shared movement arms get drawn on top. Turn Use Arms off on AFPS_WeaponObject (the validation box warns about this).

Arms Renderers is empty. The rig's arms can only be hidden for the movement-arms window if the system knows which renderers they are. Press Set Up Animations to auto-collect them, or assign them by hand.

Floating arms after dropping a weapon

Same cause: Arms Renderers is empty, so the rig's arms are never disabled. A dropped or world-pickup weapon also disables its Animator, so the arms freeze mid-pose — very visible. Assign the renderers.

The reload animation finishes before (or after) the reload

Sync Reload To Ammo Duration is off. Turn it on; the clip is then scaled to AFPS_WeaponAmmo ▸ Reload ▸ Reload Duration and the two always land together. The gameplay duration stays authoritative — the clip adapts, never the reverse. The validation box warns when a Reload clip is slotted with syncing off.

A different pool is reloading. On a multi-pool weapon only the pool at Reload Pool Index drives the clip. Check the index is the one you meant.

The reload animation keeps playing after the reload is cancelled

Cancels arrive through the same event as completion, so this should not happen. If it does with a custom graph, check that your reload states have their auto-return transition to None (exit time 1, duration 0.1) and that you kept the state names Reload / ReloadEmpty — the runtime identifies the state to leave by those names.

The weapon disappears before the holster animation finishes

The Holster slot is empty, so the switch-out is still timed by the de-equip tween settings. Fill the Holster slot and the wait re-times to the clip automatically.

If you filled it and it still cuts short, check Holster Speed Multiplier — the wait is clip length ÷ multiplier, so a multiplier above 1 shortens both together and they cannot drift apart.

Fast weapons only play part of the fire animation

That is correct behaviour. Each shot restarts the clip from frame 0, so a fire rate shorter than the clip shows the first part of it per shot. Author a shorter fire clip, or raise the fire rate interval.

No fire animation on the last round / when out of ammo

A dry fire emits no shot, so it raises no event and animates nothing. The last real round does animate — the fire check is captured before the round is consumed specifically so that shot isn't lost.

Burst weapons animate once instead of per bullet

Each burst bullet raises its own emission, so each should retrigger the clip. If it doesn't, check that Fire Crossfade is small (0.02 is the default) — a long crossfade at a fast burst rate blends the restarts into each other.

The rig snaps to a T-pose / default pose while walking or sliding

The weapon is transitioning into a locomotion state whose slot is empty. Either fill the slot, or leave Locomotion ▸ Gate Locomotion To Filled Slots on — with it on, the runtime never reports a locomotion parameter for a slot that has no clip, so the state can't be entered.

If you extended a duplicated controller and put motions on those states directly (rather than through the clip slots), the gate can't see them and will pin the parameters — turn it off in that case.

I want the sprint (or slide) animation to play while aiming

It is suppressed on purpose — those clips take the weapon off the sights and fight the procedural ADS pose. The rule lives in the template graph: remove the IsADS condition from the Walk→Sprint transition (and the IsADS exit out of Sprint) in your own copy of the controller.

The swim animation never plays

The fluid volume is set to NoSwim. That mode applies ordinary land movement, so it animates as land movement by design. Set Fluid Movement Type to Default or Swim on the AFPS_FluidMovementSettings asset.

Every swim slot is empty. With no Swim Idle to fall back on, the system reports IsSwimming false and leaves the land chain in charge. Fill at least Swim Idle.

Only the Swim Idle animation plays while swimming

That is the fallback for an empty directional slot. Fill Swim Forward / Backward / Up / Down, or leave them empty and treading water is what you get.

Swimming up plays instead of swimming forward

Vertical intent wins over forward and back on purpose — holding ascend is a deliberate act and the more distinctive pose. Swap the order in ResolveSwim if your game reads better the other way.

The slide or wallrun animation restarts every frame

Can Transition To Self is on for the Any State transition into it. The condition holds for the whole slide, so the state re-enters itself continuously. The generated template has it off; check your copy.

The weapon animates while holstered or in the world

The Animator is disabled whenever the weapon is not the current weapon, and re-enabled on equip. If you see otherwise, something else is setting animator.enabled — remove it and let AFPS_WeaponAnimator own that.

The Inspect animation never plays

Inspect After Idle Seconds is 0 (the default) — the idle timer is off. Set a value, call PlayInspect() yourself, or add an Inspect input action.

The timer also resets on any firing, reloading, aiming, movement above walking speed, or a change of movement state, so it only fires from a genuine standstill.

Animation events do nothing

The receiver is on the wrong object. Unity dispatches animation events to components on the animated GameObject itself. AFPS_WeaponAnimationEventReceiver must be on the same GameObject as the Animator, not on the weapon root.

The key doesn't match. Keys are compared exactly, case-sensitive.

The scoped sniper's arms vanish when fully scoped

Expected. ADS.ApplyScopedVisibility hides the weapon model when the scope fades in, and the rig's arms are part of that model. If you want the arms to stay, remove them from the ADS script's Objects To Hide While Scoped list.

Enter Play Mode with domain reload disabled behaves differently

It shouldn't — the system holds no mutable static state, and its hashes are pure computations. If you see a difference, check your own subclass or graph extensions for static fields that survive the reload.

Namespace AFPS

Classes

ADS

FireWeaponBase-derived ADS handler: Fire() records aim intent and a per-frame reconcile blends the aim-down-sights state (pos/rot/FOV/spread plus crosshair/scope UI). Always CanFireNow=false (no recoil kick).

AFPS_ADSPose

Shared ADS pose math. The runtime pipeline (AFPS_WeaponObject / ADS) and the editor ADS preview both evaluate the aimed pose through here, so what a designer previews in the editor can't drift from what the player actually sees.

AFPS_AI

Demo NavMesh AI: each Update steers NavMeshAgent toward the closest enemy agent.

AFPS_AbilityPickup

Pickup interactable that equips an ability into AFPS_AbilitySystem the same way AFPS_WeaponObject equips a weapon into AFPS_WeaponSystem.

Equip flow (mirrors AFPS_WeaponObject): Interact / collider pickup → Pickup(AFPS_InventorySystem) calls inventory.FindGridForItem with requireExplicitCategory=true. If a single-slot grid matches, AddItemToGrid runs and we wire onPlacedInEquipmentSlot / onRemovedFromEquipmentSlot on the resulting AFPS_ItemObject. AddItemToGrid does not fire onPlacedInEquipmentSlot, so we explicitly call EquipAbility(int, GameObject) for the slot the grid maps to.

Later drags between equipment slots and the stash run through the wired listeners (drag-out → unequip; drag-in → equip). The slot index is looked up from abilitySlotGrids, so any drag into a non-ability slot (e.g. the player rearranging into a generic stash grid) leaves AbilitySystem untouched.

Drop: reactivates the world GameObject, destroys the inventory ItemObject, unequips the ability instance from AbilitySystem, throws via rigidbody. Listener is unwired first so the teardown-side onRemovedFromEquipmentSlot doesn't re-enter the handler.

AFPS_AbilitySystem

Ability system. Holds up to maxEquippedAbilities slots (mapped to the AbilityOne/Two/Three inputs). Two equip paths coexist:

  1. Inspector loadout — designer fills AFPS.AFPS_AbilitySystem.abilities with AbilityHolder entries whose ability field points at a scene-attached AbilityBase. Those abilities are equipped from the start and are not destroyed on any unequip path.
  2. Pickup — AFPS_AbilityPickup calls EquipAbility(int, GameObject) with a prefab. The system instantiates a copy as a child, builds a runtime holder copying trigger defaults from the prefab, and the unequip path destroys the instance. Extend by inheriting AbilityBase and overriding ActivateAbility(bool pressed = true). Examples: Scripts/Abilities/Dash.cs, GrapplingHook.cs.

AFPS_Agent

Identity component for any scene actor (player or AI): stores team affiliation and exposes team/ally query helpers used by AFPS_AgentManager.

AFPS_AgentManager

Singleton manager that registers all scene AFPS_Agent instances at startup and exposes spatial queries for closest agent by team, ally, and enemy relationships.

AFPS_AmmoStateToggle

Decoupled, count-driven GameObject toggler for a weapon. Conceptually the world-space sibling of AFPS_Item's sprite-by-count system: instead of swapping a sprite asset on an inventory icon, it enables/disables child GameObjects on the weapon model based on a live count. The count comes either from AFPS_WeaponAmmo (CurrentMag / Reserve / sum) or straight from the weapon item's stored contents — summed stack sizes (StoredStackSum) or the number of distinct stored entries (StoredItemCount), mirroring SpriteCountSource.

Semantics are cumulative ranges — every entry whose [minCount, maxCount] range contains the current count is enabled simultaneously (e.g. one visible shell GameObject per loaded round, or a low-ammo warning light active only while the count is between two bounds). Pure SetActive toggling; no sprite assignment.

AFPS_AmmoStateToggle.ToggleEntry

One target GameObject and the inclusive count range over which it is enabled.

AFPS_AnimationEventEntry

One keyed cosmetic response to an animation event: an optional one-shot sound plus an optional UnityEvent for anything else (particles, prop toggles, socket spawns).

AFPS_ArmAnimationSettings

Maps each MovementState to an ArmAnimation; consumed by AFPS_ArmsController to drive the arm Animator per state.

AFPS_ArmsAnimatorContract

Single source of truth for the shared movement arms' animator: state names, parameter names, and their pre-hashed IDs. The arms mirror AFPS_WeaponAnimatorContract deliberately — same two-layer shape, same locomotion vocabulary, same swim directions — so that learning one teaches you the other, and so the two can be driven from one shared movement snapshot.

Every hash is a static readonly computed from a const string: a pure computation with no mutable static state, so it survives Enter Play Mode with domain reload disabled.

AFPS_ArmsController

Drives the shared first-person movement arms — the rig used for climbing, ledge hangs, mantles, slides and swimming, independent of whichever weapon is held.

Rebuilt on the same architecture as AFPS_WeaponAnimator: one generated template controller, a per-player AnimatorOverrideController whose named slots you drop clips into, hashed state and parameter IDs from AFPS_ArmsAnimatorContract, and playback driven by Play/CrossFade rather than triggers. Continuous poses are POLLED from the shared AFPS_MovementAnimationSampler snapshot — the same one the weapon animator reads, so the arms and the weapon can never disagree about what the player is doing. Only genuine one-shots (grab, mantle, slide-start) are pushed in by callers.

LEGACY MODE: when the assigned controller is not contract-shaped — most importantly the shipped hand-authored Arms.controller — this component behaves exactly as it always has, string parameters and triggers included. Existing projects therefore upgrade with no change in behaviour and migrate when they choose to, with the Set Up Arms Animations button on this component.

AFPS_AudioManager

Static helper for playing a random clip from a RandomAudioClipContainer at a random volume via PlayOneShot.

AFPS_Camera

First-person camera controller: processes look input, applies FOV scaling, headbob (sine or curve), hit-bob physics, wallrun/slide/movement tilt, ledge-hang yaw clamping, and vignette post-processing each LateUpdate.

AFPS_Checkpoint

Trigger checkpoint that snapshots player HP and active status effects on first contact; ResetToLastCheckpoint(AFPS_Health) restores from the frozen state on death.

AFPS_CheckpointManager

Persistent singleton that tracks the last activated AFPS_Checkpoint and restores player position, HP, and status effects on death.

AFPS_CheckpointRespawnStrategy

Respawns through the existing AFPS_CheckpointManager — same position, same frozen HP, same frozen status effects as the asset's original death behaviour. This is the strategy that keeps a project's feel unchanged when it adopts the death screen.

AFPS_ClimbMovementSettings

Wall-climb preset: detection radius/layers, PID-driven climb velocity curve, stamina drain, disconnect impulse, horizontal movement multiplier, and per-wall climb-count cap.

AFPS_Compass

Drives the HUD compass: samples camera yaw each frame and pushes heading to UIManager which fans out to the active IHUDLayer. Renderer-agnostic — UGUI and UI Toolkit HUDs share the same heading feed.

AFPS_ContainerInventory

A lootable world container — chest, crate, locker, dead body, wall stash. Interacting binds its contents to the inventory's secondary grid, resized to the size declared here, so the player loots through the same drag / rotate / stack interactions they already use on their own inventory.

Contents are live AFPS_ItemObject instances. While closed they are deactivated and parked under this GameObject, keeping their stack sizes, rotation, nested storage and the world object they were picked up from; opening re-seats them in the cells they were left in. Authored loot (startingContents, lootTable) stays as lightweight descriptors until first open.

Setup: put this on a world object with a collider on the interaction layer, and give the player an AFPS_ContainerUIController.

AFPS_ContainerLootTable

Weighted loot table for AFPS_ContainerInventory. Rolls a list of StoredItemDescriptor entries — the same serialisable shape the rest of the inventory uses for nested storage — so the result can sit dormant on a closed container and be materialised into real item objects the first time it is opened.

Two passes run per roll: guaranteed entries always attempt (gated only by their own chance), then weighted entries fill the remaining roll count, picked proportionally to weight.

AFPS_ContainerLootTable.LootEntry

One candidate line in a loot table: what can drop, how likely, and how big a stack.

AFPS_ContainerUIController

Player-side owner of the secondary ("container") inventory panel. One pooled AFPS_InventoryGrid is re-sized and re-pointed for whichever AFPS_ContainerInventory the player has open, so a 3x2 ammo box and a 10x6 corpse share the same grid, binding and UI element.

It binds and unbinds containers (one at a time), marks the grid external so the rest of the inventory treats its contents as not-yet-owned loot, drives the UXML panel (title, live weight, Close and Take All), and closes the container when the inventory closes, the player walks away, or the player dies.

Place it on the same GameObject as AFPS_InventorySystem (or anywhere in the player hierarchy) and point it at the secondary grid. The UXML fields are optional: with no UIDocument assigned it still binds containers and simply shows/hides the grid GameObject, which is what a UGUI-based setup wants.

AFPS_ControlLockStatusBehaviour

Status behaviour that locks the player's controls for the effect's duration — a Stun (lock everything), a Root/Snare (movement only), a Silence-style disarm (firing only), or any mix. Holds a reference-counted lock on AFPS_PlayerControlLock while active and releases it when the effect ends, so overlapping locks compose correctly.

Player-only: it drives the player's movement/camera/weapon systems, so it no-ops on AI (whose "stun" would be an AI-side concern). The control lock is reference-counted, so stacking two stuns and having one expire keeps the player locked until the second ends.

AFPS_CorpseContainer

Turns a dead entity into a lootable body. Watches an AFPS_Health and, the moment it dies, fills the AFPS_ContainerInventory on this GameObject with the entity's gear — a death loot table, an authored carried-items list, and optionally its equipped weapons — then enables the container so the player can interact with it.

While alive the container component is disabled, which is the interaction system's off-switch: no interaction box, no prompt, no Interact() call. A living enemy therefore shows no loot affordance without any extra wiring.

For NPCs only. On the player it refuses to run and points you at AFPS_InventoryDeathHandler, which answers the same question without riding along through respawn as a lootable body attached to the living player.

Setup: put this and AFPS_ContainerInventory on the entity (or on a child owning the corpse collider), leave the references empty to auto-resolve, and give the container a verb like "Loot". The collider the player looks at must be on the same GameObject as the container — the interaction system reads the collider it hits, and does not walk up to parents.

AFPS_CrosshairSettings

Maps MovementState → Crosshair; UIManager selects the active entry each frame and transitions via IHUDLayer.

AFPS_CrouchAndSlideSettings

Crouch and slide preset: speed thresholds, collider height, movement force/drag, slide impulse, and ceiling-clearance check distance.

AFPS_DamageNumberManager

Spawns world-space floating damage/heal numbers in response to OnDamageDealt. Only renders hits dealt by the local player (instigator with an AFPS_Agent flagged isPlayer). Numbers are pooled TMPro.TextMeshPro objects built procedurally (no prefab), billboarded to AFPS.AFPS_DamageNumberManager.cam, animated via the curves on AFPS.AFPS_DamageNumberManager.settings. Rapid hits on the same target inside the accumulation window merge into one growing number.

AFPS_DamageNumberSettings

Preset driving AFPS_DamageNumberManager: world-space floating damage/heal numbers — text style, crit and heal colouring, rise/fade animation, and same-target accumulation. One asset can be shared by every weapon's hit feedback.

AFPS_DamageType

ScriptableObject identity for a kind of damage (Ballistic, Fire, Poison, …). Replaces the old DamageType enum so new types can be authored as assets and carry data: a display name and colour for UI, a death-screen noun, and an optional list of status effects to auto-apply on a direct hit. Referenced by type, type, weapon/explosion settings, and damageType.

AFPS_DashSettings

Dash preset: every tuning value for Dash — direction mode and force, the pre-dash velocity reset, the momentum the dash keeps afterwards, and the optional charge-up windup.

Swap the asset to swap the whole feel of the dash. Only the SFX containers stay on the component, since those are per-instance rather than per-preset.

AFPS_DeathBodyHandler

Optional companion to AFPS_DeathController that decides what the camera is looking at during a death. A freezecam or orbit shot pointed at a hidden first-person capsule looks broken — this is what gives those modes a subject.

Add it to the player only when the death screen actually leaves first person; the controller works fine without it. Whatever this produces is written back into body, which is the transform every camera mode frames.

AFPS_DeathCameraMode

Base class for everything the camera can do while the player is dead. Subclass, override Sample(DeathContext, float), and the asset gets a new death camera with no changes to the death controller — the same extension model as AbilityBase.

Subclasses only describe where the camera wants to be; the blend from the pose the player died holding into that target is handled here so every mode gets easing, dolly-in, and FOV blending for free.

Runtime state: modes are shared assets, so any per-death state a subclass caches must be reset in Begin(DeathContext). The shipped modes are pure functions of elapsed time and the context.

AFPS_DeathController

Owns the window between dying and respawning. Add it to the player and Die() stops respawning instantly and hands the death over here instead; remove it and the asset reverts to its original instant-checkpoint behaviour. Nothing else has to change either way — the presence of this component is the switch.

The sequence itself is described entirely by the AFPS_DeathSettings asset in settings: timing, camera mode, respawn strategy, screen text, and policy. Swapping that one asset is how a flat "YOU DIED" overlay becomes a killcam.

Runs at a late execution order so its camera drive lands after AFPS_Camera has had its turn, and times everything on the unscaled clock so death-screen countdowns survive time dilation.

AFPS_DeathScreenUGUI

UGUI death screen, for projects still on the Canvas-based HUD. Functionally identical to AFPS_DeathScreenUIToolkit — same contract, same settings, same behaviour — so the two can be swapped on the controller without touching anything else.

Every reference is optional: wire up only the pieces the screen actually shows.

AFPS_DeathScreenUIToolkit

UI Toolkit death screen, rendered from UI Toolkit/DeathScreen/DeathScreen.uxml. Matches how the pause and main menus are built in this asset: a UnityEngine.UIElements.UIDocument on its own GameObject, elements resolved by name, styling left entirely to USS.

Every element is optional — delete the countdown label or the prompt from the UXML and this keeps working. Only the names matter, so a project can rebuild the layout from scratch as long as it keeps them.

AFPS_DeathScreenView

Base for whatever draws the death screen. AFPS_DeathController talks to this and nothing else, so the UGUI and UI Toolkit implementations are interchangeable — and a project can subclass this to render the screen its own way without touching the death flow.

Leaving the controller's view slot empty is a supported configuration: the death sequence still runs its camera, timing, and respawn, it just draws no UI. That is how a purely cinematic death (freezecam into an automatic respawn) is authored.

AFPS_DeathSettings

One death screen, described end to end: how long the sequence runs, what the camera does, what happens to the body, what the screen says, and what brings the player back.

Swapping this one asset on AFPS_DeathController is the whole customisation story — the shipped presets in Presets/Death are the same component configured four different ways.

AFPS_DragableObject

Physics-driven holdable object: PID controllers drive position and optionally rotation toward a camera-relative hold point each FixedUpdate; auto-releases when distance exceeds disconnectDistance.

AFPS_EquipAnimationWeaponObjectSettings

Weapon equip/de-equip animation preset: resting position/rotation, equip start/end transforms, and per-axis LeanTween duration and easing.

AFPS_EventRespawnStrategy

Does nothing itself — raises OnRespawnRequested and lets your own code decide where the player goes. This is the escape hatch for anything the shipped strategies don't cover: a networked spawn handshake, a spectator queue, a wave-based arena that spawns you when the round flips.

Subscribe before the player can die (Awake/OnEnable on a manager), move the player in the handler, and set restoresHealth to match whether your handler also sets HP.

AFPS_Explosion

OverlapSphere explosion: LOS wall-check per collider, falloff-curve damage, self-damage/force toggles, and an optional self-destruct timer.

AFPS_ExplosionMovementSettings

Explosion response preset: toggles input-disable and drag-override on blast hit, with per-explosion duration controlled by the caller.

AFPS_FOVEffectsCameraSettings

Velocity-driven FOV preset for main and weapon cameras. The peak velocity FOV is a multiplier of the (runtime-mutable) base FOV, reached as the player approaches their configured top movement speed — so the effect scales with both the player's chosen FOV and their movement tuning, with no manual velocity threshold to keep in sync.

AFPS_Fluid

Trigger volume that writes fluid state into AFPS_Movement on enter/exit and applies linearDamping to non-player rigidbodies.

AFPS_FluidMovementSettings

Fluid (swim/water) preset: movement mode (Default/Swim/NoSwim), swim speed, acceleration, and ascend/descend rates.

AFPS_FollowBodyDeathCamera

Third-person camera that tracks the body — the corpse prefab or ragdoll produced by AFPS_DeathBodyHandler, or the player transform when neither exists. Pairs with a ragdoll: the camera hangs back at a fixed offset while the body tumbles, so the fall is readable.

AFPS_FootstepSettings

ScriptableObject map from PhysicsMaterial → AudioResource for surface-driven footstep sounds; defaultAudioResource plays on unmapped surfaces.

AFPS_FreezeDeathCamera

Holds the exact camera pose the player died with — the classic freezecam. The camera stops being driven by the body, so it no longer bobs, tilts, or follows a ragdoll falling over: the last frame of gameplay simply hangs there.

The optional dolly and drift turn that frozen frame into a slow reveal without leaving the pose: pull back to show the room the player died in, rise to look down at the body, or add a barely perceptible yaw so the shot doesn't read as a screenshot.

AFPS_GrapplingHookSettings

Grappling hook preset: every tuning value for GrapplingHook — attach rules, reel and momentum, pendulum tension, swing control, movable-anchor mass split, and the auto-detach conditions.

Swap the asset to swap the whole feel of the grapple. Scene-bound references (the rope LineRenderer) and the SFX containers stay on the component, since those are per-instance rather than per-preset.

AFPS_GroundingAndSlopeMovementSettings

Grounding and slope preset: sphere-cast radius/distance/layers, slope max-angle and push force, and PID-driven float/step-height controller tuning.

AFPS_HeadbobCameraSettings

Procedural headbob preset: Sine or Curve mode, velocity-scaled frequency/amplitude, per-state suppression, and stabilization tuning.

AFPS_Health

Core HP component: manages base HP and overheal pools, per-type damage resistances, status effect lifecycle, death/respawn flow via AFPS_CheckpointManager, and drives AFPS_UIManager health HUD.

AFPS_HealthAffectArea

Trigger volume that applies a signed HP delta to any AFPS_Health occupant on an independent per-target timer, routing negative deltas through ApplyDamage(DamageInfo) (typed) and positive through Heal(float).

AFPS_HealthBar

World-space health bar for the AFPS_Health on this object (or a parent). Builds a billboarded UGUI bar (background + left-anchored fill) procedurally — no prefab or material to wire. The fill tracks base HP (overheal excluded) and recolors by the discrete thresholds on AFPS.AFPS_HealthBar.settings. Add this to any entity that should show a bar; the player typically uses the screen HUD instead.

AFPS_HealthBarSettings

Shared preset for AFPS_HealthBar: bar dimensions, placement, background, and discrete per-threshold fill colors. One asset can drive every entity's bar.

AFPS_HitBobCameraSettings

Acceleration-driven camera bob preset: acceleration scale/clamp, rebound, damping, and per-axis rotation multipliers for physics-impact shake.

AFPS_Hitbox

Per-collider damage relay for body-part criticals. Sits on a child collider of a character (head, torso, limb), scales incoming damage by AFPS.AFPS_Hitbox.damageMultiplier, can optionally bypass the owner's per-type resistance and the firing weapon's range falloff, tags the hit with AFPS.AFPS_Hitbox.region for crit styling, then forwards the result to the owning AFPS_Health. Implements IDamageable so weapons can apply damage to the exact collider they hit without knowing whether it is a hitbox or the body itself. Radius damage (AFPS_Explosion) targets AFPS_Health directly and therefore never receives this multiplier.

AFPS_Hitmarker

UGUI hitmarker instance: runs start→base→end LeanTween sequence driven by AFPS_HitmarkerSettings, then self-destructs.

AFPS_HitmarkerSettings

Three-phase hitmarker preset (start→base hold→end): sprite, sound + delay, per-phase size/rotation/color and LeanTween easing.

AFPS_HorizontalMovementSettings

Ground and air movement preset: drag, acceleration, max speed, and air-strafe speed for both grounded and airborne states.

AFPS_InputManager

Bootstraps the static AFPS_PlayerActions instance, applies saved keybindings, enables the Player action map, and exposes ToggleActionMap for UI/gameplay context switches.

AFPS_Interactable

Base for anything the player can target and interact with. Holds only look-and-interact concerns: the UI label, the held-press timer, and the Interact/EndInteract verbs. Inventory pickup lives on AFPS_PickupInteractable.

Off-switch API: set interactable.enabled = false to make AFPS_InteractionSystem ignore this object entirely — no interaction box, no name/description UI, no Interact() callbacks. Useful while a dying object plays its death/explosion effect on a delay before Destroy(). Disable also stops the host MonoBehaviour's Update/FixedUpdate (relevant for subclasses like AFPS_DragableObject which run physics per-frame).

AFPS_InteractionCollider

Trigger collider that auto-picks up AFPS_PickupInteractable objects with PickupType.OnTouch on overlap; non-pickup interactables are ignored and must be reached via the spherecast path in AFPS_InteractionSystem.

AFPS_InteractionSystem

Player interaction controller: runs dual spherecasts each Update (weapon and general layers), manages look-targeting UI, routes press/held-press events to Interact(AFPS_InteractionSystem) or Pickup(AFPS_InventorySystem), and owns the active AFPS_DragableObject reference.

AFPS_InventoryDeathHandler

Decides what happens to the player's inventory when they die: keep it, drop it into a lootable container at the death position, or destroy it.

Hooks OnDied, which fires before either respawn path runs, so the death position is still the player's real one. Nothing else in the death system touches the inventory, so this component is the whole feature — remove it and deaths keep everything.

Dropped items keep their identity: stack sizes, rotation, nested storage, and the world objects they were picked up from all survive into the container, so looting your own grave returns exactly what you lost.

Drop To Container can put the loot in its own container on the ground, or inside the corpse the death sequence spawns so the body itself is the stash — see DeathContainerPlacement. This is the player's body-loot component; AFPS_CorpseContainer is the NPC equivalent and refuses to run alongside it.

Setup: put it on the player next to AFPS_InventorySystem, leave the references empty to auto-resolve, and pick a policy. Drop To Container additionally needs a prefab carrying an AFPS_ContainerInventory.

AFPS_InventoryGrid

A single inventory grid panel: allocates a cell array, enforces category/size constraints, exposes weight and capacity queries, and sets gridOnMouse on pointer entry.

AFPS_InventoryGridUIBinding

Per-grid UI Toolkit renderer. Coexists with UGUI renderer (hidden via CanvasGroup). Owns cellPixelSize (panel-space). On first layout: sets baseRes=Screen.size (disables system's adjustedCellSize scaling) and cellSize=cellPixelSize*panelScale (on-screen px). Multiple bindings cooperate — keep cellPixelSize uniform (last-write-wins otherwise).

AFPS_InventorySystem

Grid-based inventory system: manages item placement, stacking, rotation, swapping, drag-hold, right-click menus, and double-click consolidation across multiple AFPS_InventoryGrid instances.

AFPS_InventoryUIRenderer

Top-level UI Toolkit renderer. Hides the original UGUI inventory canvas and draws a "held item" mirror VisualElement that follows the mouse, mirroring inventorySystem.currentItem each frame (sprite, size, rotation).

Pair with one AFPS_InventoryGridUIBinding per AFPS_InventoryGrid. All coordinate conversions go through the binding's PanelPerScreen helper so the renderer is robust to PanelSettings scale-mode changes.

AFPS_InventoryWeightDisplay

Binds UI Toolkit weight labels to live AFPS_InventoryGrid weights. Per-group: each PanelWeightGroup sums its grids into one Label. Top-bar: optional aggregate label. Uses GetGridWeight (includes nested storage via GetTotalWeight).

AFPS_InventoryWeightDisplay.PanelWeightGroup

Binds a named UXML Label to one or more grids whose weights are summed and formatted into it each frame.

AFPS_Item

Item definition: grid size, stack, weight, category, storage container settings, count-driven sprite/HUD icon swaps, and context menu reference.

AFPS_ItemCategory

Tag SO used by grids and items to enforce category-based placement restrictions.

AFPS_ItemInteractable

Plain (non-weapon) pickup interactable. Interact: base.Pickup → add to inventory, reparent + disable GO. Refused if no grid fits (no input consumed). Drop: base.Drop reactivates GO, then positions in front of camera and launches with dropForce + dropTorque. Use AFPS_WeaponObject for equip-on-pickup weapon behavior.

AFPS_ItemMenu

List of button prefabs spawned as the right-click context menu for an inventory item.

AFPS_ItemMenuController

UGUI IItemMenuRenderer. Wraps CreateItemMenu/DestroyCurrentItemMenu so InventorySystem dispatches uniformly across UGUI and UI Toolkit.

AFPS_ItemMenuUIToolkit

UI Toolkit IItemMenuRenderer. Spawns a floating VisualElement menu with one Button per AFPS_ItemMenu entry. Per-button logic is delegated: each prefab (UGUI ItemMenuButtonBase) is instantiated off-screen, SetItem+OnPress, then destroyed — Consume/Drop/Use/etc. work unchanged. Self-registers as activeItemMenu in Initialize, overriding the UGUI controller. Mirrors IHUDLayer pattern.

AFPS_ItemObject

Runtime UI representation of an inventory item: manages grid position, rotation, stack count, sprite display, storage sub-items, and equipment-slot event callbacks.

AFPS_KeepFirstPersonDeathCamera

Leaves the camera exactly where it is — the player keeps their own first-person view, and can keep looking around, while the death screen sits on top. This is the mode behind a flat "YOU DIED" overlay with a respawn button.

AFPS_KillerDeathCamera

Killcam: frames whoever landed the killing blow, resolved from the latched LastDamage instigator. The camera sits over the victim's body and looks down the line to the killer, keeping them framed as they move.

Deaths with nothing to blame — a fall, drowning, a status effect that outlived its caster — have no killer to point at. Set fallbackWhenNoKiller so those still play something deliberate instead of holding a shot of empty air.

AFPS_KnockbackStatusBehaviour

Status behaviour that knocks the player back and strips their control until they land again — the classic "launched and helpless" effect. On apply it launches the player's Rigidbody away from whoever applied the effect (plus an upward kick) and holds a control lock that releases itself the moment the player touches the ground; the effect's own duration is a safety cap that also releases the lock if the player somehow never lands.

Player-only (drives the player's Rigidbody + control lock). Direction comes from the effect's instigator (instigator) — so a rocket, a punch, or a barrel blast all shove the player away from the source.

AFPS_Ladder

Climbable ladder surface: sets AFPS_Movement.currentLadder via trigger overlap or explicit Interact depending on useInteractionSystem.

AFPS_LadderMovementSettings

Ladder preset: climb/jump behaviour enums, PID-driven climb and X/Z snap controllers, fall speeds, boost/disconnect impulses, and loose-mode angle limits.

AFPS_MantleAndVaultMovementSettings

Mantle/vault and ledge-hang preset: dual-ray detection offsets, slope allowance, timed forward/up impulses, max hang duration, drop-back force, and mantle-abort grace period.

AFPS_MovePosition

Each LateUpdate snaps this transform's position to target.position + offset.

AFPS_MoveRotation

Each LateUpdate copies target.rotation onto this transform.

AFPS_MoveSpeedStatusBehaviour

Status behaviour that scales the target's movement speed while active — the "Cold slows you" effect. Registers a multiplier on the target's AFPS_Movement in OnApplied(AFPS_StatusContext) and removes it in OnExpired(AFPS_StatusContext), keyed by the effect instance so multiple slows stack and each cleans up independently. No-ops on targets without an AFPS_Movement (e.g. AI actors).

AFPS_Movement

Core FPS player controller: PID hover-float, Air strafing, wallrun, multi-jump, climb, ledge hang, mantle/vault, ladder, slide, sprint, stamina, fluid, and moving-platform rider support.

AFPS_MovementAnimationSampler

Builds an AFPS_MovementAnimationSnapshot from an AFPS_Movement.

This exists so the swim and locomotion rules live in exactly one place. They were duplicated the moment a second animation system needed them, and duplicated rules drift: the arms and the weapon disagreeing about whether the player is swimming is a bug nobody would think to look for.

Pure and allocation-free — safe to call every frame, and safe under Enter Play Mode with domain reload disabled (no static state of any kind).

AFPS_MovementEffectsCameraSettings

Camera roll/tilt preset: mouse tilt, strafe tilt, wallrun tilt, slide tilt, and ledge-hang yaw soft/hard clamp tuning.

AFPS_MovingPlatform

Kinematic rigidbody platform: interpolates between waypoints or spins as a rotator, carries riders via per-frame delta, and supports dwell, ping-pong, loop, and elevator EndModes.

AFPS_OrbitDeathCamera

Slowly circles the body — the cinematic death shot. Radius and height can widen over the orbit, so the camera both pulls away from and rises above the death as it goes around, which is what sells a long "hold until the player presses respawn" screen.

AFPS_PickupInteractable

Abstract base for interactables that route through the inventory system on pickup. Concrete subclasses: AFPS_ItemInteractable (generic item w/ physical drop), AFPS_WeaponObject (equip-on-pickup).

AFPS_PlayerActions

Provides programmatic access to UnityEngine.InputSystem.InputActionAsset, UnityEngine.InputSystem.InputActionMap, UnityEngine.InputSystem.InputAction and UnityEngine.InputSystem.InputControlScheme instances defined in asset "Assets/Axiom FPS/AFPS_PlayerActions.inputactions".

AFPS_PlayerControlLock

Reference-counted control lock on the player. Status effects (Stun, Knockback) — or any other system — hold a lock over one or more AFPS_ControlAxes; the player regains a channel only when the LAST holder suppressing it releases, so overlapping locks never fight. Also supports "lock until the player lands again" for knockback.

Added automatically to the player the first time a lock is requested (like the status VFX registry) — you never place it by hand. It drives MovementLocked, allowCameraInput, and allowFiring, saving and restoring the look/firing flags so releasing a lock can't stomp a menu that independently disabled them.

AFPS_PlayerSoundManager

Routes movement events (jump, air-jump, land, sprint, slide, footsteps) to AudioSources; footstep interval scales inversely with speed.

AFPS_RecoilController

Drives camera-rotation, weapon-rotation, and weapon-position recoil for the weapon this is attached to. Writes to AFPS_WeaponObject.recoilQuaternion / .recoilPos and AFPS_Camera.recoilQuaternion — the same fields AFPS_WeaponSystem.Update() and AFPS_Camera.LateUpdate() compose into final transforms.

Maintains an independent solver triplet + pattern/momentum tracker PER profile, so a weapon with multiple fire scripts (each with its own AFPS_RecoilProfile) doesn't lose mid-decay spring state when fire modes switch. ApplyToHost sums every cached profile's current outputs each frame.

On a weapon swap, the outgoing controller keeps ticking its camera-channel springs until they decay below CamDecayEpsilonSqr — so in-flight camera recoil decays smoothly through the swap instead of snapping to zero. Weapon-mesh channels (rotation + position) reset immediately since the mesh is no longer visible. A static frame marker coordinates the shared camera field write so the decaying outgoing controller and the active incoming controller compose multiplicatively rather than race-overwriting each other.

Authoring asset for per-weapon recoil: three independent channels (camera rotation, weapon rotation, weapon position), Procedural or Scripted pattern mode, and momentum build/cap.

AFPS_RespawnStrategy

Where the player comes back. Swapping this asset turns a checkpoint game into an arena shooter without touching the death screen, the camera, or any code — which is the point of keeping it separate from AFPS_DeathSettings.

Spawns a prefab when this entity's AFPS_Health dies, forwarding the killer (this entity's last attacker) to the spawned object so any damage it deals is credited to whoever caused the death — not to this object. AbilityBase

Base for all abilities. Subclass and override ActivateAbility(bool) for press/release abilities or ActivateAbility(float) for charge abilities.

AbilityFire

Bridges the ability system into the weapon system: a fire script that activates an AbilityBase instead of emitting a shot, so any ability can be the way a weapon fires. Drop it into a weapon's primary or secondary fire scripts and the weapon's existing pipeline — fire type, fire rate, burst, recoil profile, sprint interrupt, equip/drop — drives the ability.

Dash

Impulse dash with three direction modes, an optional charge-up windup, and a momentum window that decides how much of the dash the player keeps.

The dash fires a single UnityEngine.ForceMode.Impulse along one of three directions — the camera's aim, the player's movement input, or straight up (see DashMode) — scaled by a ground or air force. The two modes that can launch the player off the ground suppress AFPS_Movement's hover float for a moment, because the float PID holds a fixed hover height and would otherwise push back against the launch.

Momentum preservation is a drag window rather than a force: the controller's ground and air acceleration only ever add speed along the movement vector, so nothing brakes a dash except UnityEngine.Rigidbody.linearDamping, which AFPS_Movement rewrites from its own state every frame. For momentumPreserveTime seconds after a dash this script re-applies a scaled-down damping on every physics step — reading the controller's authored value through CurrentDrag rather than the body's own, so several physics steps inside one frame can't compound the reduction. The window ends early when the player lands, jumps, slides, or steers hard against the dash, so it never fights the action the player just chose.

The optional charge-up bleeds speed off in place for a windup and then fires automatically, hanging the player in the air (gravity and float cancelled) and locking movement input for the duration if the preset asks for it. Aim stays free throughout, and the dash direction is sampled when the impulse actually fires, so the player can steer a charged dash with the mouse.

The windup is the ability's own, and is independent of the holder's trigger type: pairing it with a Charge-type holder gives the player a held charge followed by this windup, and the holder's trigger rate starts counting from the press rather than from the moment the impulse lands.

Every tuning value lives on an AFPS_DashSettings preset, so the whole feel of the dash swaps with one asset. Only the per-instance SFX containers stay on the component.

GrapplingHook

High-velocity, momentum-driven grapple

On press a ray sets a fixed world-space anchor. While held, the Rigidbody is reeled toward the anchor with an eased "windup" pull that ramps to full force, and is constrained to an inextensible, ratcheting rope so it swings as a pendulum; movement input adds perpendicular swing force for player-driven arcs. The rope conserves and compounds kinetic energy, so releasing slingshots the player forward with the accumulated momentum.

Anchors may be movable: hooking a non-kinematic UnityEngine.Rigidbody reels both ends toward each other and splits the rope between them by mass, so a crate flies to the player while a boulder pulls the player instead. See AFPS.GrapplingHook.BindAnchor(in UnityEngine.RaycastHit) for the split and AFPS.GrapplingHook.ApplyRopeForcePair(UnityEngine.Vector3, UnityEngine.ForceMode) for how each rope term is shared. Static geometry, kinematic bodies and anything past the mass ceiling behave exactly as before, and the rope end tracks a moving anchor so the LineRenderer stays glued to it.

Auto-detaches when the player crouches, is reeled all the way to the anchor (slingshotting past it), looks too far away from the anchor, drives face-on into a solid obstacle, loses line of sight along the rope for long enough that it would be running through a wall, or the anchor body is destroyed mid-swing. The grapple is released by letting go of the button

All physics is applied through UnityEngine.Rigidbody forces — the transform is never moved directly — and both Update and FixedUpdate are written to avoid managed allocations (no Debug.Log, no allocating physics queries, struct-only math).

Every tuning value lives on an AFPS_GrapplingHookSettings preset, so the whole feel of the grapple swaps with one asset. Only the per-instance references — the rope LineRenderer and the SFX containers — stay on the component.

IDeathSequence

Implemented by whatever owns the window between dying and respawning. Die() looks for one on its own GameObject and, if HandleDeath(AFPS_Health) accepts, stops there — leaving isDead latched and handing the entity over.

The contract is deliberately one method: the presence of the component is what switches the asset from the legacy instant-checkpoint respawn to a full death sequence, so projects that never add one behave exactly as they did before. AFPS_DeathController is the shipped implementation.

IHUDLayer

Renderer-agnostic HUD contract. UGUI and UI Toolkit both implement it; AFPS_UIManager calls these as one-way pushes. Implementations must tolerate null args and out-of-order calls (e.g. SetAmmo before SetWeaponInfo on a fresh equip).

Class AFPS_ADSPose

Shared ADS pose math. The runtime pipeline (AFPS_WeaponObject / ADS) and the editor ADS preview both evaluate the aimed pose through here, so what a designer previews in the editor can't drift from what the player actually sees.

ComputeAimedOffsets(Vector3, Vector3, Transform, out Vector3, out Vector3)

The offsets ADS blends toward at full aim. They're composed against the resting offsets so that at full aim the aim point lands exactly on the weapon system's origin (which sits on the camera in the stock rig) AND is oriented down the camera's forward axis.

Both halves of the aim point's local transform are honoured. Rotating the aim point rotates the weapon by the inverse, which is how sight cant is corrected: point the aim point down the optic's true line of sight and the weapon tilts to match. An aim point with identity rotation reduces exactly to the previous behaviour (aimed rotation = identity, offset = -localPosition), so existing weapons are unaffected.

ComputeBase(AFPS_WeaponSystem, AFPS_EquipAnimationWeaponObjectSettings, out Vector3, out Vector3)

Resting (hip) local offsets for a weapon parented to weaponSystem. Mirrors what AFPS_WeaponObject writes into basePos/baseRot each frame, but takes the system and settings explicitly so the editor can evaluate it for a weapon that isn't equipped (weapons are only parented to the system at runtime, so an unequipped weapon has no basePos). Missing references degrade to a zero offset rather than throwing — the editor evaluates this against half-authored prefabs where the runtime path never would.

EvaluatePose(Vector3, Vector3, Transform, float, float, out Vector3, out Quaternion)

Local pose at the given raw (un-eased) aim blends, with every procedural contribution (bob/sway/recoil/tilt/bump/equip) omitted — those are all zero at rest anyway, and are exactly what an editor preview can't reproduce. Position and rotation take separate blends because ADS drives them on independent transition timings.

GetAimPointLocalPose(Transform, Transform, out Vector3, out Quaternion)

The aim point's pose expressed in weaponRoot's local space — i.e. relative to the transform AFPS_WeaponSystem writes the composed offsets onto. Collapses to the aim point's own localPosition/localRotation when it is a direct child of the root (every stock weapon), and stays correct when it is nested deeper. Degrades to identity on missing references.

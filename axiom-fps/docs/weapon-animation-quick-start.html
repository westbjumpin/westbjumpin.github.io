Weapon Animation — Quick Start

Axiom FPS animates weapons in two layers that run at the same time:

  • The procedural pipeline (equip tween, bob, sway, tilt, recoil, bump, ADS) moves the whole weapon around the camera. It has always been there and it keeps running.
  • The clip system on this page plays authored animation clips on the weapon's own rig — arms and moving parts — underneath that.

Every clip slot is optional. A weapon with no clips behaves exactly as it always has, so nothing you already built changes when you upgrade.

Note

Before the first use in a fresh project, run Tools ▸ AFPS ▸ Generate Weapon Animator Template once. It creates the shared template controller and its placeholder clips.

The five steps

  1. Import an animated weapon FBX. The rig should contain the arms and the weapon's moving parts, animated together in the same clips — the standard layout for FPS animation packs on the Asset Store. Import settings are covered in Importing an animation pack.

  2. Make it the weapon's model. Drop the FBX into a weapon prefab as a child and assign it to AFPS_WeaponObject ▸ Base ▸ Weapon Model. If the weapon already had a static model, replace it.

  3. Add the component and press the button. Add AFPS Weapon Animator to the weapon root (the object with AFPS_WeaponObject on it), then press Set Up Animations. That adds an Animator to the model if it needs one, creates a per-weapon AnimatorOverrideController from the shipped template, assigns it, and collects the rig's arm renderers.

  4. Drag clips into the slots. The component's inspector lists every slot: Idle, Walk, Sprint, Slide, Wallrun, Swim Idle, Swim Forward, Swim Backward, Swim Up, Swim Down, Equip, Fire, Fire (ADS), Reload, Reload (Empty Mag), Inspect, Holster. Fill the ones you have. Slots you leave empty are labelled (procedural fallback) and keep their existing behaviour — the weapon simply never enters that state.

  5. Press Play. Equip plays on draw, Fire plays per shot, Reload is speed-matched to the weapon's reloadDuration, the switch-out waits for the Holster clip, and the Speed / IsSprinting / IsADS parameters are fed for you.

Tip

Setting up a weapon without opening its prefab: Tools ▸ AFPS ▸ Weapon Animation Setup does the same thing from one window — drop the prefab in and use the same button and slot list.

Where things must live

Weapon prefab (root)          ← AFPS_WeaponSystem composes this transform
├─ AFPS_WeaponObject
├─ AFPS_WeaponAnimator        ← here, on the ROOT
└─ Weapon Model (child)
   └─ Animated rig from the FBX
      ├─ Animator             ← here, NEVER on the root
      ├─ AFPS_WeaponAnimationEventReceiver   (optional, for clip SFX/events)
      └─ Renderers (arms + weapon parts)

The Animator must not sit on the weapon root. The weapon system rewrites the root's position and rotation every frame, and an Animator there would fight it. The inspector reports this as an error if it happens.

What the inspector checks for you

The validation box at the bottom of AFPS Weapon Animator re-runs on every repaint and flags:

  • an Animator on the weapon root, a missing override controller, or Apply Root Motion left on (errors — playback will be wrong);
  • culling mode not set to Always Animate, Use Arms left on for a full rig (you would see four arms), no arm renderers assigned, or a Reload clip with duration syncing switched off (warnings);
  • the list of slots still running procedurally (info).

Sound and effects from clips

Add AFPS Weapon Animation Event Receiver to the same GameObject as the Animator, then add animation events to your clips calling AnimEvent with a string key (MagOut, MagIn, BoltBack…). Each key maps to an optional AudioClip and a UnityEvent.

Important

Animation events are cosmetic only. Never drive ammo, damage, or weapon state from them. Gameplay timing is owned by AFPS_WeaponObject and AFPS_WeaponAmmo, and clips get retimed, interrupted and speed-synced — anything gameplay-critical wired to a keyframe will desync.

World Containers and Looting

Chests, crates, weapon lockers, wall stashes and lootable corpses all reduce to the same problem: show the player a second grid, let them drag between it and their own inventory, and make sure nothing in that second grid counts as theirs until they physically move it across.

AFPS_ContainerInventory solves that by reusing the inventory the player already knows. There is no separate loot screen and no separate item representation — a container binds its contents to the secondary grid in the inventory UI, and every interaction the player has already learned (drag, rotate, stack, split, right-click menu) works on loot unchanged.

The pieces

Component Lives on Job
AFPS_ContainerInventory The world object Declares grid size and access rules, owns the contents
AFPS_ContainerUIController The player Owns the one pooled secondary grid and the UXML panel
AFPS_ContainerLootTable ScriptableObject Weighted loot rolls
AFPS_CorpseContainer A dying entity Turns death into a lootable body
AFPS_InventoryDeathHandler The player Decides what death does to the player's own inventory

Only one container is open at a time, and only one grid ever exists for them. The controller re-sizes and re-points that single grid at whichever container the player opened, so a 3×2 ammo box and a 10×6 corpse cost the same as one grid.

Player setup (once)

The player prefab already ships with a disabled Secondary Grid GameObject carrying an AFPS_InventoryGrid and an AFPS_InventoryGridUIBinding bound to the secondary-grid UXML element. All that's missing is the controller:

  1. Add AFPS_ContainerUIController next to AFPS_InventorySystem.
  2. Point Inventory System at the inventory, Container Grid at the Secondary Grid object, UI Manager at the UI manager, and Document at the inventory UIDocument.
  3. Optionally set Player Health so an open container closes when the player dies.

Leave Max Grid Size at 10×6 unless you've resized the panel — it clamps containers that ask for more space than the UXML has.

The container grid must not appear in the inventory system's Player Inventory Grids array. That array defines what the player owns: carry weight, pickup routing and ammo counts all read from it. The controller logs an error at Awake if the container grid is listed there, because the symptoms otherwise show up far from the cause — loot adding to carry weight, or world pickups silently disappearing into a hidden grid.

Making a container

Put AFPS_ContainerInventory on any object with a collider on the interaction layer.

  • Grid Size — the footprint the container presents. This is the whole point of a container: a small crate reads as a small grid.
  • Allowed Categories — empty accepts everything. Fill it for themed storage (an ammo crate that only takes Ammo).
  • Max Item Size Limit — refuses items whose base footprint is bigger than this, rotation-agnostic. (0,0) for no limit.
  • Starting Contents — hand-authored loot. The entries are StoredItemDescriptors, the same shape used for nested storage everywhere else, so a chest can start with a backpack that already holds a loaded magazine.

Set the inherited Interaction Verb to something like Open; adding the component sets that up for you.

Loot tables

Create one via Create → AFPS → Inventory System → Container Loot Table.

Each entry has a weight (relative likelihood in the weighted draw), a stackRange (clamped to the item's own stackCount), a chance, and an optional nested storedItems list. Entries flagged Guaranteed are resolved in their own pass and don't consume one of the weighted picks — that's where the quest item or the always-present key goes.

Loot Timing decides when the roll happens:

  • OnSpawn — rolled in Start. Cheapest to reason about; combined with a non-negative Loot Seed the same container holds the same loot every session.
  • FirstOpen (default) — deferred until the player actually reaches it.
  • EveryOpenWhenEmpty — restocks. Vendor stashes and respawning supply crates.

A roll produces descriptors, not objects. Nothing is instantiated until the container is first opened, so a level full of unvisited crates costs almost nothing.

Locks

Set Locked and assign a Key Item. The player only needs to be carrying the key; opening consumes it when Consume Key On Unlock is set, and Relock On Close turns a consumed key into one-shot access. Interacting while locked fires On Locked Interact instead of opening — wire a sound or a prompt there. Leaving Key Item empty makes the lock scripted-only: nothing in the player's inventory will open it until some other system clears locked.

How contents survive being closed

Contents are live AFPS_ItemObject instances, not a serialised snapshot. When the container closes, whatever is left in the grid is deactivated, re-parented under the container GameObject, and remembered along with the exact cell and rotation it was sitting in. Opening again re-seats each item where the player left it.

That matters for three things a snapshot would lose:

  • Nested storage. A magazine looted half-loaded stays half-loaded.
  • The world object. An item that was originally picked up off the ground keeps its connectedInteractable, so dropping it later returns the original GameObject rather than spawning a copy.
  • Layout. Players arrange loot piles; re-flowing them on every open feels broken.

If the container's declared grid size shrinks between opens, items whose cells no longer exist are re-placed in the first free spot instead of being dropped. If there genuinely isn't room, they stay parked and a warning names them.

Dropping items that never had a world object

Loot rolled from a table has no source GameObject to return to. Assign World Prefab on the AFPS_Item asset — a prefab with an AFPS_ItemInteractable (or AFPS_WeaponObject) whose Item Type points back at the same asset — and the Drop menu button will spawn it, carrying stack size and nested contents onto it exactly like a normal drop. Items with neither a source object nor a World Prefab are left in place, and Drop logs which asset needs the prefab.

Moving things across

Three ways, all of them respecting category filters, footprint and carry weight:

  • Drag. Ordinary inventory drag between the two grids.

  • Modifier + click. Hold the modifier set in the inventory system's Quick Transfer Modifier (Shift by default) and click an item to send it where it belongs. With a container open it resolves in priority order:

    1. Item in the container → into the player's storage.
    2. Item in an equipment slot → back into the player's storage, never straight into the container. Stripping gear and stashing it are separate decisions, and one click shouldn't make both.
    3. Item in the player's storage with a free slot claiming its category → equip it.
    4. Anything else → into the container.

    With no container open, the same gesture equips or files the item — see Shift-click outside a container.

  • Take All. The TAKE ALL button in the container panel header. It moves large items first — transferring a 1×1 before a 2×4 can otherwise leave the big item homeless in an inventory that had room for both.

A gamepad has no modifier to chord with, so the same routing gets a button of its own: the Inventory/QuickTransfer action, bound to the left shoulder by default. It acts on whatever the controller cursor is over and follows the identical priority order, with or without a container open. Rebind it like any other action.

The Transfer and Equip item-menu buttons do the same thing from the context menu if you would rather surface it there too.

When a transfer is refused

Refusals are reported on the side that caused them. If the player's inventory has no room, the usual HUD warning flashes. If the container is the one refusing, the message appears across the bottom of its grid and names it — AMMO CRATE IS FULL, or WEAPON RACK WON'T TAKE THAT when its Allowed Categories reject the item. A generic "inventory full" would be misleading there, since the player's own inventory is fine.

Both strings are on the controller (Container Full Message / Container Rejected Message, {0} = the container's title), along with Message Duration. Clear the Message Element Name field, or use a UXML without a #secondary-message label, and container refusals fall back to the HUD warning.

Shift-click outside a container

The same modifier (and the same gamepad button) works with no container open, and follows the same rules minus the container:

  1. Item in an equipment slot → back into the player's storage. Identical to rule 2 above, so stripping gear reads the same whether or not a chest is in front of them.
  2. Otherwise → an equipment slot that claims its category, then a grid that explicitly claims it — an ammo pouch, a weapon rack.

Wildcard grids are never targeted, so the gesture can't shuffle an item between general stashes for no reason. An item with no home simply stays put, silently; the click is consumed either way, so it never surprises the player by lifting something it couldn't place. The one refusal that is reported is a failed unequip, which means their storage is full and the gear stayed on.

Carry weight

Weight is enforced at the boundary, not on every move. An item already in the player's grids costs nothing extra to rearrange — gating that would leave an over-encumbered player unable to put their own item back down. An item crossing out of a container and into player storage is weighed, and refused with the usual HUD warning if it would break maxCarryWeight. Swaps subtract the weight of whatever they displace, so trading a heavy item for a lighter one always works.

Lootable corpses

AFPS_CorpseContainer is the NPC side of body looting; the player's own body is AFPS_InventoryDeathHandler's job, and the corpse container refuses to run on a player or alongside that component rather than dropping the same gear twice.

It sits next to an AFPS_ContainerInventory on the entity and watches its AFPS_Health. While alive, the container component is disabled — which is the interaction system's documented off-switch, so a living enemy shows no interaction box, no prompt and no loot affordance without any extra wiring.

On death it fills the container from its Death Loot Table and Carried Items, optionally adds whatever the entity had equipped (Include Equipped Weapons, which reads AFPS_WeaponSystem.equippedWeapons and needs each weapon's Item Type assigned), and enables the container.

Death Loot Seed is separate from the container's own seed and defaults to -1 (random), so every body drops its own loot. Set a fixed value only for a scripted, one-of-a-kind corpse — it makes every instance of that prefab drop identically.

Lootable For Seconds closes the loot window after a delay; leave it at 0 for bodies that stay lootable. For bodies that should disappear once picked clean, set Destroy When Emptied on the container instead, with a Destroy Delay long enough for whatever On Emptied drives.

The collider matters. The interaction system reads the AFPS_Interactable on the collider it hits and does not walk up to parents (that is what AFPS_Hitbox exists for on the damage side). Whatever the player aims at must be on the same GameObject as the AFPS_ContainerInventory — a ragdoll's bone colliders are not.

Lifetime conflicts. Lootable For Seconds runs independently of anything else that removes the body, so a corpse wired to DestroyHPGameobject on On Died, or carrying an AFPS_SpawnOnDeath with Destroy Owner On Death, can vanish before the player reaches it. The component detects both and warns; turn off Warn On Lifetime Conflict if the combination is deliberate.

Death and the player's inventory

Nothing in the death system touches the inventory on its own, so by default a player respawns with everything. AFPS_InventoryDeathHandler on the player adds the other two options:

  • Keep (default) — untouched. Arcade and campaign games.
  • Drop To Container — everything moves into a lootable container, for the player (or anyone else) to loot back. Extraction shooters. Placement decides where that container is:
    • Spawn At Death Position (default) — drop the container prefab on the ground. Works with any death setup.
    • Attach To Corpse — put the loot inside the body itself, so the player loots their own corpse. Needs an AFPS_DeathBodyHandler in Spawn Corpse Prefab mode whose prefab carries an AFPS_ContainerInventory (plus a collider on the interaction layer). If no corpse turns up, it warns and falls back to spawning the container — the inventory is never lost to a setup mistake.
  • Destroy All — everything is lost. Roguelikes.

It hooks AFPS_Health.OnDied, which fires before either respawn path runs, so the death position is still the player's real one rather than wherever they respawned. OnDied also fires before the death sequence spawns a body, so Attach To Corpse captures what the player was carrying at death and completes the move a frame later, once the corpse exists.

Dropped items are the same objects the player was carrying, handed to the container through AdoptItem — stack sizes, rotation, nested storage and the world objects they were originally picked up from all survive, so looting your own grave returns exactly what you lost. Weapons in equipment slots fire their onRemovedFromEquipmentSlot callback on the way out, so they unequip cleanly.

Exemptions

Exempt Categories lists categories the player keeps regardless of policy — the secure-container idea: quest items, keys, insured gear. Exempt Equipment Slots keeps whatever is in single-item slots, so the player respawns still armed and only loses their bags.

An item on the cursor when they die is included, unless it came out of an open container — that loot was never theirs, and the panel closing returns it.

Sizing the drop

Auto Size To Contents grows the spawned container's grid so a full inventory fits in as few visits as possible. It sizes against the player's Max Grid Size — the real display limit — rather than the prefab's own width, so a prefab authored as a small crate doesn't cap a full inventory into a fraction of the available space. Sizing is best-effort, working off total footprint area with headroom, since exact bin-packing isn't worth the cost.

An inventory can still hold more than the panel can show. The overflow waits inside the container and drops into the grid as the player loots space free, without them having to close and reopen it. Nothing is lost, only staggered.

Snap To Ground raycasts down from the death position so dying mid-air doesn't leave a floating stash. The ray skips the player's own colliders, which are still standing at the death spot when it runs.

The death position is sampled every frame while the player is alive, not read when the death fires. Respawn teleports the player, and whether that has already happened by the time a death listener runs depends on death-sequence and UnityEvent listener ordering — sampling makes the drop position the death position by construction, so a grave can never appear at the spawn point.

Recolouring an icon per item

AFPS_Item has a Sprite Tint — a colour multiplied over the item's inventory icon everywhere it is drawn: the grid, the drag ghost, equipment slots, and the uGUI example. White, the default, leaves the sprite exactly as authored.

It exists so one sprite can serve several items. The shipped VSK rifle's ammo is a tinted variant of the standard rifle round rather than a second piece of art, and the same trick covers rarity tiers, faction variants, or a greyed-out placeholder without a new texture per item.

Anything drawing an item icon in your own UI should call AFPS_ItemObject.GetDisplayTint() rather than reading the sprite directly — it returns the item's tint, or white when the item has no data, which is what keeps every view agreeing.

Closing behaviour

There is no close button on the panel. While the inventory is open the interaction system refuses to fire at all, so the player can neither re-interact with the open container nor reach anything else in the world through the panel — which means the only ways out are the ones that make sense:

  • Closing the inventory (the toggle key) closes the container with it.
  • Walking away, past the container's Auto Close Distance.
  • Dying, when the controller's Player Health is assigned.

By default walking away closes the whole inventory, not just the container panel — leaving the player standing in the world rather than staring at a half-empty loot screen. Turn off Close Inventory On Walk Away on the controller if you'd rather their own inventory stayed open where they left it.

An item still on the cursor when the container closes is returned to the container first, so nothing is ever destroyed mid-drag. If the container has no room left for it, the inventory system's Held Item Revert Fallback decides what happens — and note that the spill-to-another-grid strategy never spills into a container, so the player can't accidentally gift an item to a chest they were walking away from.

Events

AFPS_ContainerInventory exposes On Opened, On Closed, On Emptied, On Locked Interact and On Unlocked as UnityEvents for animation, audio and quest hooks. On Opened fires after the contents are visible; On Closed fires after they've been parked, so it's safe to animate the lid from either.

Importing an Animation Pack

Axiom FPS expects the standard Asset Store FPS animation layout: one rig containing the arms and the weapon's moving parts, animated together in the same clips. Because the hands and the weapon are keyframed in the same take, hand-to-weapon contact is correct by construction — there is no runtime IK, no retargeting, and nothing to sync.

The system itself is skeleton-agnostic. Any rig works as long as the clips were authored against it.

FBX import settings

Select the FBX and set:

Model tab

Setting Value Why
Scale Factor as authored (usually 1) A mismatched scale shows up as arms the wrong size relative to the weapon.
Import Cameras / Lights off Nothing needs them.
Optimize Game Objects off by default Optimizing strips the bone hierarchy, which also removes the transforms you need addressable — muzzle sockets, shell-eject points, magazine objects. Turn it on only once the weapon is finished, and add every socket you use to Extra Transforms to Expose.

Rig tab

Setting Value Why
Animation Type Generic Weapon rigs are not humanoid, and Generic avoids the muscle-space retarget that would distort finger placement on the grip.
Avatar Definition Create From This Model on the mesh FBX; Copy From Other Avatar on clip-only FBXs One avatar shared by the mesh and every clip file keeps the bone mapping identical.
Root node the rig's root bone Only matters if the pack authored root motion.

Animation tab

Setting Value Why
Import Animation on
Root Transform Position (Y/XZ), Rotation Bake Into Pose Prevents the clip from translating the model away from the weapon root that the procedural pipeline is positioning.
Loop Time on for Idle / Walk / Sprint only The action clips are one-shots and return to None on exit time.
Apply Root Motion (on the Animator, not the importer) off Root motion would drive the model's transform and fight the weapon root. Forced off at runtime; the inspector flags it as an error.

Also set the Animator's Culling Mode to Always Animate. A first-person weapon is never off-screen, and a culled Animator pops when it resumes. This is also forced at runtime and flagged by the inspector.

Re-skinning the arms

Animation packs ship with their own arm meshes. To use your own:

  1. Keep the pack's skeleton — the clips are authored against it.
  2. Skin your arm mesh to that skeleton in your DCC tool and export it as part of the same FBX (or as a separate FBX using Copy From Other Avatar).
  3. Delete the pack's arm mesh from the prefab; leave the bones.
  4. Re-run Set Up Animations, or fix Arms Renderers by hand — it must list your arm meshes so they hide correctly when the weapon is dropped, holstered, or during climb and mantle.

Sharing one arm mesh across several weapon FBXs is worth doing where the pack allows it: it keeps the player's hands visually consistent between weapons and saves memory.

Building the weapon

  1. Drop the FBX into the weapon prefab as a child.
  2. Assign it to AFPS_WeaponObject ▸ Base ▸ Weapon Model.
  3. Turn Use Arms off. The rig carries its own arms; leaving it on draws the shared movement arms on top of them.
  4. Move the weapon's existing sockets — muzzle point, shell eject, adsPoint — onto the corresponding bones of the new rig, so they ride the animation. In particular, ADS's ADS Point should be a child of the weapon body bone; the ADS system samples it once when you start aiming, so it follows the idle animation naturally.
  5. Add AFPS Weapon Animator, press Set Up Animations, and fill the slots.

Splitting clips

If the pack ships one long take with a clip list, split it in the FBX's Animation tab as usual. Names do not matter to Axiom FPS — the slot you drag a clip into is what decides when it plays, so you can use the pack's own naming freely.

Two rigs in one FBX

Some packs export the arms and the weapon as two separate armatures inside one FBX, animated together. That works unchanged: it is still one Animator, one set of clips, and one model child.

AFPS_AbilityPickup

Pickup interactable that equips an ability into AFPS_AbilitySystem the same way AFPS_WeaponObject equips a weapon into AFPS_WeaponSystem.

Equip flow (mirrors AFPS_WeaponObject): Interact / collider pickup → Pickup(AFPS_InventorySystem) calls inventory.FindGridForItem with requireExplicitCategory=true. If a single-slot grid matches, AddItemToGrid runs and we wire onPlacedInEquipmentSlot / onRemovedFromEquipmentSlot on the resulting AFPS_ItemObject. AddItemToGrid does not fire onPlacedInEquipmentSlot, so we explicitly call EquipAbility(int, GameObject) for the slot the grid maps to.

Later drags between equipment slots and the stash run through the wired listeners (drag-out → unequip; drag-in → equip). The slot index is looked up from abilitySlotGrids, so any drag into a non-ability slot (e.g. the player rearranging into a generic stash grid) leaves AbilitySystem untouched.

Drop: reactivates the world GameObject, destroys the inventory ItemObject, unequips the ability instance from AbilitySystem, throws via rigidbody. Listener is unwired first so the teardown-side onRemovedFromEquipmentSlot doesn't re-enter the handler.

AFPS_AbilitySystem

Ability system. Holds up to maxEquippedAbilities slots (mapped to the AbilityOne/Two/Three inputs). Two equip paths coexist:

  1. Inspector loadout — designer fills AFPS.AFPS_AbilitySystem.abilities with AbilityHolder entries whose ability field points at a scene-attached AbilityBase. Those abilities are equipped from the start and are not destroyed on any unequip path.
  2. Pickup — AFPS_AbilityPickup calls EquipAbility(int, GameObject) with a prefab. The system instantiates a copy as a child, builds a runtime holder copying trigger defaults from the prefab, and the unequip path destroys the instance. Extend by inheriting AbilityBase and overriding ActivateAbility(bool pressed = true). Examples: Scripts/Abilities/Dash.cs, GrapplingHook.cs.

AFPS_AmmoStateToggle

Decoupled, count-driven GameObject toggler for a weapon. Conceptually the world-space sibling of AFPS_Item's sprite-by-count system: instead of swapping a sprite asset on an inventory icon, it enables/disables child GameObjects on the weapon model based on a live count. The count comes either from AFPS_WeaponAmmo (CurrentMag / Reserve / sum) or straight from the weapon item's stored contents — summed stack sizes (StoredStackSum) or the number of distinct stored entries (StoredItemCount), mirroring SpriteCountSource.

Semantics are cumulative ranges — every entry whose [minCount, maxCount] range contains the current count is enabled simultaneously (e.g. one visible shell GameObject per loaded round, or a low-ammo warning light active only while the count is between two bounds). Pure SetActive toggling; no sprite assignment.

AFPS_RecoilController

Drives camera-rotation, weapon-rotation, and weapon-position recoil for the weapon this is attached to. Writes to AFPS_WeaponObject.recoilQuaternion / .recoilPos and AFPS_Camera.recoilQuaternion — the same fields AFPS_WeaponSystem.Update() and AFPS_Camera.LateUpdate() compose into final transforms.

Maintains an independent solver triplet + pattern/momentum tracker PER profile, so a weapon with multiple fire scripts (each with its own AFPS_RecoilProfile) doesn't lose mid-decay spring state when fire modes switch. ApplyToHost sums every cached profile's current outputs each frame.

On a weapon swap, the outgoing controller keeps ticking its camera-channel springs until they decay below CamDecayEpsilonSqr — so in-flight camera recoil decays smoothly through the swap instead of snapping to zero. Weapon-mesh channels (rotation + position) reset immediately since the mesh is no longer visible. A static frame marker coordinates the shared camera field write so the decaying outgoing controller and the active incoming controller compose multiplicatively rather than race-overwriting each other.

GrapplingHook

High-velocity, momentum-driven grapple

On press a ray sets a fixed world-space anchor. While held, the Rigidbody is reeled toward the anchor with an eased "windup" pull that ramps to full force, and is constrained to an inextensible, ratcheting rope so it swings as a pendulum; movement input adds perpendicular swing force for player-driven arcs. The rope conserves and compounds kinetic energy, so releasing slingshots the player forward with the accumulated momentum.

Auto-detaches when the player crouches, is reeled all the way to the anchor (slingshotting past it), looks too far away from the anchor, or drives face-on into a solid obstacle. The grapple is released by letting go of the button

All physics is applied through UnityEngine.Rigidbody forces — the transform is never moved directly — and both Update and FixedUpdate are written to avoid managed allocations (no Debug.Log, no allocating physics queries, struct-only math).

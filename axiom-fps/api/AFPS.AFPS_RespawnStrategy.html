Class AFPS_RespawnStrategy

Where the player comes back. Swapping this asset turns a checkpoint game into an arena shooter without touching the death screen, the camera, or any code — which is the point of keeping it separate from AFPS_DeathSettings.

Subclass and override Respawn(DeathContext) to add your own (a spawn queue, a network handshake, a spectator hand-off).

RestoresHealth

True when this strategy sets the player's HP itself — a checkpoint restores the HP frozen at the checkpoint, so the controller must not overwrite it with a full heal. Strategies that only move the player leave this false and get healed to full for them, otherwise the player respawns on 0 HP and dies again on the next tick.

ApplySpawnFacing(DeathContext, Quaternion)

Points the player's view down a spawn direction. Rotating the body alone does nothing to where the player is looking — AFPS_Camera owns yaw in its own accumulator and would snap the view straight back to the pre-death heading on the first frame of restored control. Pitch is levelled at the same time so nobody respawns staring at the floor they died on.

TeleportPlayer(DeathContext, Vector3, Quaternion, bool)

Moves the player to a spawn pose, going through the Rigidbody rather than the transform. The player body uses interpolation, so a bare transform write keeps rendering from the un-moved physics pose and the player appears never to have left the spot — the same trap ResetToLastCheckpoint(AFPS_Health) documents. Velocity is zeroed here; AFPS_DeathController re-zeroes it across the following physics steps to absorb any explosion impulse still queued from the death itself.
